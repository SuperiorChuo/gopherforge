# 开放平台 Webhook 第一批实施计划

## 目标

提供租户隔离的开放平台 Webhook 管理面：管理员创建订阅、选择审计事件动作、一次性取得签名密钥、启停/重置密钥并查看投递记录。后台从 `audit_logs` 事实表按游标生成投递任务，使用 HMAC-SHA256 签名发送，支持幂等事件 ID、超时、指数退避和失败停投。微服务与 monolith 使用同一持久化语义，单体不引入 NATS。

## 分诊

`audit/shared`、迁移、网关与前端管理底座属于基础设施，需同步 `go-admin-kit-micro`，并按单进程形态移植 `go-admin-kit-monolith`。主仓需部署 migration、audit、frontend；下游仅本机构建验证。

## 步骤与验收

1. **持久化与共享安全组件**：新增订阅、投递、游标表；实现 endpoint 校验、HMAC 规范签名与 SSRF 防护。
   - 验收：shared/audit 聚焦单测，迁移 fresh Up。
2. **Audit 管理 API 与 worker**：订阅 CRUD、密钥一次性展示/重置、投递列表；按 audit_logs 游标 fanout，投递 worker 支持幂等、超时和退避。
   - 验收：`bash scripts/verify.sh audit`
3. **管理界面与契约**：新增 `/system/webhooks` 页面、菜单、权限、路由及 OpenAPI；状态完备，密钥只在创建/重置后显示一次。
   - 验收：`bash scripts/verify.sh frontend`、`bash scripts/verify.sh contract`
4. **三线同步与真实闭环**：micro 精确同步；monolith 移植本地 worker，不引入 NATS；部署 109，以临时接收器验证真实审计事件、HMAC、重试/禁用和零残留。
   - 验收：下游 audit/server + web build/lint；109 E2E；1280/390 0 overflow/0 console error/warn。

## 范围边界

- 不新增 API Key/服务账号体系：现有 OAuth2 `client_credentials` 已覆盖机器身份、scope、限流、吊销和 introspection。
- 第一批仅开放审计事件动作，不转发敏感 before/after 全量快照；载荷只含必要元数据，避免秘密与个人数据外泄。
- 不允许公网任意 URL 绕过 SSRF 防护；默认只允许 HTTPS，内网/loopback 仅测试显式注入策略，不持久化生产豁免。
- 不在单体引入 NATS、Outbox worker 或服务拆分。
- 不实现入站 Webhook、任意业务 payload 映射或可执行脚本。
